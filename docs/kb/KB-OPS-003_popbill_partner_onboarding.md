# KB-OPS-003: 팝빌 파트너 가입 실행 가이드

> **상태**: 미실행. **2026-09-15 기준 SETIVE 는 사업자등록이 없다(확정).** Phase 0 만 수행 가능하며, Phase 1(사업자등록)이 나머지 전체의 하드 게이트다.
>
> 사업자등록이 없는 동안 **벤더 API 검증은 팝빌·볼타 양쪽 모두 불가능하다** — 팝빌은 연동신청 폼이 사업자번호·업태·종목을 필수로 요구하고 TESTER 공개키도 차단돼 있으며(§9), 볼타는 워크스페이스 생성에 사업자등록증 기준 회사 정보와 체크섬 유효한 사업자등록번호를 요구한다. **타인의 사업자번호를 쓰지 않는다.**
> 연계 아키텍처는 [KB-KOR-006](./KB-KOR-006_etax_invoice_integration.md), 자격증명 보관은 [KB-OPS-002](./KB-OPS-002_tenant_integration_credentials.md).

## 1. 전체 흐름과 게이트

```
 Phase 0  결정 고정 · ContactUs 접수 · SDK 스모크        ← 사업자등록 불요
    │
 Phase 1  사업자등록                                      ← 하드 게이트
    │
 Phase 2  연동신청 제출 → API Key(LinkID/SecretKey) 메일 수령
    │
 Phase 3  담당자 유선 협의 — 파트너 결제와 단가를 여기서 확정
    │
 Phase 4  테스트 환경 구축 (테스트포인트 · 테스트인증서 · FLE 키 · 웹훅)
    │
 Phase 5  운영전환 신청 → 계약 (전자 1일 / 등기 최소 5일)
    │
 Phase 6  운영 개시 — 환경 재구축 · 테넌트 온보딩 · 첫 실발행
```

> **2026-09-15 팝빌 공식 회신으로 확정**: *"당사 서비스는 사업자 대상 서비스를 원칙으로 하고 있어, 사업자 등록 전 단계에서의 이용은 어렵습니다. 사업자 등록 완료 후 '연동 문의' 또는 '연동 신청'을 통해 재접수를 진행해 주시기를 부탁드립니다."* → **Phase 1 우회 경로는 없다.**
>
> 같은 회신: *"추후 사업자 정보가 변경될 경우, 파트너 계약, LinkID, API KEY를 포함한 모든 연동 환경이 새롭게 재설정됩니다."* → **법인 설립 직후 정보가 안정된 뒤에 연동신청한다.** 상호·주소 변경이 흔한 시점에 신청하면 재설정을 두 번 한다.

**직렬 잠금**: LinkID 가 없으면 개발자센터의 기술문의·버그신고·테스트포인트·테스트인증서·운영전환 **어느 것도 접수할 수 없고**, 공개 테스트키 `TESTER` 도 토큰 발급이 차단돼 있다([KB-KOR-006](./KB-KOR-006_etax_invoice_integration.md) §10). **"먼저 기술 검증하고 계약을 결정한다"가 성립하지 않는다.**

| 구간 | 소요 |
|---|---|
| 사업자등록 | 개인 즉시~3영업일 / 법인 설립등기 포함 1~2주 (+ 국세청 반영 1~2일) |
| 연동신청 → API Key | **SLA 미공개** |
| 테스트 환경 구축 | 2~3주 (각 신청의 처리 대기가 직렬로 끼어든다) |
| 계약 | **전자 1일 이내 / 등기 최소 5일** ← 유일하게 SLA 가 명시된 구간 |
| 운영 환경 재구축 | 1~2주 |
| **합계 (등록 보유 시)** | **6~10주** |

> 첫 담당자 통화에서 각 구간의 실제 소요일을 **한 번에 물어** 이 표를 실측값으로 갱신한다.

## 2. Phase 0 — 지금 할 수 있는 것 (사업자등록 불요)

### 2.1 먼저 정할 것

| 결정 | 왜 지금인가 |
|---|---|
| **개인사업자 vs 법인** | 법인은 전자계약에 **법인명의 범용 공동인증서**(1년 80,000원 / 3년 180,000원)가 필수. 없으면 폼 JS 가 전자계약 입력을 지우고 **등기계약(최소 5일)으로 강제**한다. 개인사업자는 대표자 휴대폰 인증만으로 1일 이내, 인증서 비용 0원. 팝빌 폼이 사업자번호 중간 2자리(80~89=법인)로 자동 판정한다 |
| **상호·대표자·업태·종목·주소** | 연동신청 폼에서 한 번, 테넌트 가입 `JoinMember` API 에서 다시 쓰인다(`CorpName` 200자 / `CEOName` 100자 / `Addr` 300자 / `BizType` 100자 / `BizClass` 100자). 운영전환에서 사업자등록증과 대조되므로 **등록증 기재 그대로** 맞춘다 |
| **요금 모델** | 파트너 결제는 리셀링 **"해당 없음(원가 제공)"**, 연동회원 결제는 "지원(원가+마진)". SETIVE 가 원하는 "테넌트에 요금 미표시 + 합산 차감"은 정확히 파트너 결제지만 **그 대가로 건당 마진이 사라진다.** 구독료에 원가를 녹이는 요금표를 먼저 만들어 성립을 확인한다 |
| **신청할 API 상품 집합** | §2.3 |
| **파트너 계정 ID/PW** | §3.2. **되돌릴 수 없다** |
| **조직 공용 담당자 이메일 별칭** | LinkID/SecretKey 가 이 주소로만 오고 **재조회 경로가 문서에 없다.** 개인 메일 금지 |

### 2.2 ContactUs 로 사전 접수

`www.popbill.com/ContactUs` — 사업자번호·업태·종목·ID/PW 를 **묻지 않는 유일한 경로**다. 필수는 담당자명·연락처·이메일·서비스선택·문의내용(최대 10,000자)이고 회사명은 선택이다.

문의 본문에 넣을 것: "ERPNext 기반 멀티테넌트 클라우드 ERP SaaS, 테넌트를 연동회원으로 등록, **파트너 결제 희망**, 현재 사업자등록 진행 중" + [KB-KOR-006](./KB-KOR-006_etax_invoice_integration.md) §9.2 의 질의 11항목.

### 2.3 신청할 상품 집합 (지금 결정)

체크박스 11개가 모두 `name="item"` 이고 검증은 최소 1개뿐이라 **복수 선택에 제한이 없다.**

| 구분 | 상품 (value) |
|---|---|
| **필수** | 전자세금계산서 (110) |
| **함께 권장** | 사업자등록상태조회/휴폐업조회 (170) · 계좌조회 (180) · 예금주조회 (182) |
| 검토 | 홈택스수집 (111) · 기업정보조회 (171) · 전자명세서 (120) · 현금영수증 (140) |
| 보류 | 문자 (150) · 카카오톡 (154) · 팩스 (160) |

**왜 지금 더 고르는가**: 미등록 상품을 호출하면 *"호출한 API 상품에 이용 권한이 부여되지 않아 사용이 제한됩니다"* 오류가 나고, 해결은 **연동문의를 통한 담당 부서 수작업 처리**다(SLA 없음). 스프린트 중에 걸리면 그 스프린트가 날아간다. 반면 **함께 신청해도 기본료·도입비가 0원**이고 테스트 환경은 무료 포인트로 제공된다.

> ⚠ 팝빌 FAQ 가 테스트 포인트 추가 신청에 *"일부 원가 발생 서비스 제외"* 라고 적는다. 계좌조회처럼 원가가 발생하는 서비스는 테스트 포인트 지원이 제한될 수 있다 — **어떤 상품이 해당하는지 미확인, 담당자 통화에서 확인**.

### 2.4 환경 스모크 (컨테이너)

```bash
COMPOSE=docker/development/docker-compose.yml
# env/bin/pip 여야 한다. 시스템 파이썬에 설치하면 bench 가 못 찾는다
docker compose -f "$COMPOSE" exec -T backend \
  /home/frappe/frappe-bench/env/bin/pip install -q popbill
docker compose -f "$COMPOSE" exec -T backend python -c "import popbill; print(popbill.__file__)"
# 아웃바운드 직결 확인 — auth.linkhub.co.kr / popbill-test.linkhub.co.kr / popbill.linkhub.co.kr
docker compose -f "$COMPOSE" exec -T backend python -c \
  "import socket,ssl; s=ssl.create_default_context().wrap_socket(socket.create_connection(('auth.linkhub.co.kr',443),5),server_hostname='auth.linkhub.co.kr'); print(s.version())"
```

> ⚠ **popbill SDK 는 프록시를 타지 않는다.** `popbill/base.py` 와 `linkhub/linkhub.py` 가 `http.client.HTTPSConnection` 을 직접 생성하고 프록시 처리 코드가 **전혀 없어** `HTTPS_PROXY` 를 무시하며, ssl 컨텍스트도 만들지 않아 **시스템 CA 번들에만 의존**한다. requests 로 다른 API 는 잘 되는데 팝빌만 안 되는 형태라 원인 찾기가 어렵다. 직결 경로를 확보하거나, 불가능하면 REST 를 requests 로 호출하는 얇은 클라이언트를 만든다.
>
> ⚠ SDK 의 `python_requires` 가 없고 classifiers 가 3.10 까지만 표기한다. `datetime.utcnow()` 등 deprecated API 를 쓰므로 **컨테이너 파이썬에서 import 스모크가 필요**하다.

## 3. Phase 2 — 연동신청 폼

### 3.1 제출 경로를 하나로 고정한다

`www.popbill.com/PartnerRequest` (권장) 와 `developers.popbill.com/customer-center/partner-request` 는 **필드명·서비스 코드가 동일한 같은 신청서**다. 둘 다 내면 **같은 신청이 두 건 접수**된다.

www 를 권장하는 이유: 주소가 '주소' + '상세 주소' 두 칸으로 나뉘고, 비밀번호 허용 문자 검증이 더 엄격해 **www 를 통과하면 양쪽 모두 통과**한다.

### 3.2 필드별 입력값

| 필드 | 필수 | 입력 |
|---|---|---|
| `item` (서비스 선택) | ✅ | §2.3 집합. 복수 선택 |
| `corpNum` (사업자번호) | ✅ | 숫자만 입력하면 3-2-5 자동 하이픈(maxlength=12). **검증은 "10자리 숫자"뿐 — 체크섬도 국세청 대조도 없다.** 등록증을 보며 한 자리씩 확인 |
| `corpName` / `ceoName` | ✅ | 등록증 기재 그대로(법인격 표기 방식까지) |
| `bizType` / `bizClass` (업태/종목) | ✅ | 자유 텍스트(각 100자), 선택 목록·코드 조회 없음. 등록증 기재 그대로. SaaS/ERP 의 통상 기재는 업태 '정보통신업', 종목 '소프트웨어 개발 및 공급업' 계열이나 **실제 값은 세무 대리인·홈택스 등록 결과를 따른다** |
| `address` + `detail-address` | ✅ | '주소 찾기' 버튼(`/Zipcode` 팝업). 제출 시 JS 가 **구분자 없이 이어 붙이므로** 상세 주소 앞에 공백 1칸을 넣는다. 등기계약 가능성이 있으면 **우편물 수령 가능한 주소** |
| `id` (아이디) | ✅ | **6~50자, 영문+숫자만 권장.** 두 폼의 허용 특수문자 집합이 달라(www 는 `:` 불허) 영숫자가 안전. **중복확인 버튼이 없어** 중복은 제출 후에야 드러난다 → 조직 고유 문자열+숫자 |
| `password` | ✅ | **8~20자, 영문 대·소문자·숫자·특수문자 각 1자 이상.** 허용 특수문자 중 `!@#$%^&*` 범위만 쓴다 — 백슬래시·따옴표는 셸/설정 파일 이스케이프 사고를 부른다 |
| `contactName` / `contactEmail` / `contactTel` | ✅ | **조직 공용 이메일 별칭.** API Key 수신처다 |

> **이 ID/PW 는 "테스트 환경 계정"이 아니라 파트너 계정이다.** 폼 툴팁 원문: *"입력하신 계정 정보는 테스트 환경(test.popbill.com)과 운영 환경(popbill.com)에서 동일하게 사용되므로 팝빌 서비스에서 별도로 회원가입하지 마시기 바랍니다."* `partner.popbill.com`(파트너 관리자)에도 자동 가입된다.

### 3.3 제출 전 반드시

**입력값을 별도 문서에 먼저 기록한다.** 제출 성공 시 `location.reload()` 가 폼을 비우고, **신청 내역 조회 화면도 수정·취소 UI 도 없다.** 비밀번호는 어디서도 다시 볼 수 없다.

## 4. Phase 3 — 담당자 통화에서 확정할 것

**파트너 결제는 연동신청 폼에도 운영전환 폼에도 선택란이 없다.** 요청하지 않으면 기본 연동회원 결제로 갈 수 있고, 그러면 테넌트가 각자 충전하며 요금·잔여포인트가 노출된다 — **SETIVE 요구와 정반대다.**

→ **연동신청 직후 통화에서 확정하고 메일로 근거를 남긴다.** 운영 전환 후 `GetChargeInfo` 의 `chargeMethod` 로 코드 검증한다.

같은 통화에서 함께 처리할 것:
- **FLE(필드 레벨 암호화) 키 요청** — 개발자센터 고객지원 메뉴 9개 어디에도 신청 폼이 없다. **유일하게 안내된 경로는 파트너센터(1600-8536) 전화다.** 이 키가 없으면 `registTaxCertPFX` 가 막혀 인증서 등록에서 멈춘다
- 각 구간의 실제 SLA
- IP Whitelisting 신청 채널 (보안체계 페이지가 항목만 나열하고 설명이 없다)
- [KB-KOR-006](./KB-KOR-006_etax_invoice_integration.md) §9.2 의 미해결 질의

## 5. Phase 4 — 테스트 환경

| 신청 | 경로 | 입력 |
|---|---|---|
| 테스트 포인트 | `/customer-center/testpoint` | **테스트기간 · 테스트건수 · 예상 운영전환 시점** 3값. 미리 정하지 않으면 폼 앞에서 멈춘다 |
| 테스트 공동인증서 | `/customer-center/requestcert` | LinkID + 사업자번호. 메일로 파일 전달 |
| 웹훅 통합 URL | `partner@linkhubcorp.com` **메일 수기 접수** (API 없음) | §5.1 |

### 5.1 웹훅 — 처음부터 파트너 통합 URL 로

*"고객사는 하나의 유형만 선택하여 설정 가능"*, *"URL 유형 변경 시 기존 URL 정보 해지를 선행 요청"*. **멀티테넌트라면 처음부터 파트너 URL 이어야 한다** — 테넌트가 늘 때마다 메일을 보내는 구조는 SaaS 에서 성립하지 않는다.

| 항목 | 규격 |
|---|---|
| 포트 | **80 · 443 · 9854 만 허용.** 그 외는 등록은 되지만 이벤트가 전부 실패 |
| 인증 | **기본값 '미사용'** — 지정하지 않으면 엔드포인트가 공개되고 상태 이벤트를 위조당할 수 있다. 신청 메일에 Basic 또는 API Key 를 명시 |
| 응답 | `200` + `OK` 또는 `{"result":"OK"}`. **200 만 주고 본문을 비우면 5분 간격 4회 재전송** |

개발 초기에 **'웹훅 이용 환경: 테스트'로 미리 신청**해 리드타임을 흡수한다.

### 5.2 인증·토큰 설정

| 항목 | 함정 |
|---|---|
| `IPRestrictOnOff` | 기본값 `True` 는 토큰을 **발급 시점 IP 에 묶고**, SDK 가 사업자번호별로 토큰을 **30분 메모리 캐시**한다. 컨테이너 재배치·NAT 변경으로 이그레스 IP 가 바뀌면 **워커마다 다르게 실패**하는 재현 어려운 증상이 나온다 → `UseStaticIP`(`static-*.linkhub.co.kr`, 52.78.164.186 / 13.124.222.90) 또는 `IPRestrictOnOff=False` 중 무엇인지 **배포 전에 결정**하고, 인증 실패를 '토큰 재발급 후 1회 재시도'로 감싼다 |
| `UseLocalTimeYN` | 기본값 `True` 는 **로컬 시각을 서명 문자열에 넣는다.** 몇 분만 틀어져도 모든 호출이 인증 오류가 된다 → NTP 보장 또는 `False`. 인증 실패 로그에 **컨테이너 UTC 시각을 함께** 남긴다 |
| `SecretKey` 보관 | 팝빌 공식 튜토리얼이 `settings.py` 평문 예시다. **SecretKey 하나면 파트너 계정 전체와 하위 모든 연동회원 API 접근이 열리고**, 파트너 결제 구조에서는 SETIVE 포인트가 직접 차감돼 금전 피해로 직결된다 → [KB-OPS-002](./KB-OPS-002_tenant_integration_credentials.md) |

## 6. Phase 5 — 운영전환

`developers.popbill.com/customer-center/serviceopen`

1. **입력 순서를 지킨다** — 폼 JS 가 `.contractType` 하위 input 을 건드릴 때마다 `corpNum` 길이가 12 가 아니면 **값을 지우고 사업자번호 칸으로 스크롤**한다. 순서: 사업자번호 → LinkID → 담당자 → API 상품 → (법인이면 인증서 라디오) → 계약담당자.

## 7. Phase 6 — 운영 개시

### 7.1 테스트 → 운영으로 넘어가는 것은 **파트너 계정 ID/PW 뿐**이다

팝빌 원문: *"테스트 환경과 운영 환경은 독립적인 시스템으로 구성되어 운영전환시 **데이터 이관 또는 공유가 불가**합니다."*

**전부 다시 해야 한다**: 연동회원 · 공동인증서 · 웹훅 URL · 국세청 전송 설정 · 포인트 · 발행이력.

→ 테스트에서 한 설정을 **목록으로 적어 두고** 운영에서 하나씩 재현한다. **파일럿 고객 온보딩은 운영전환 이후로 배치**한다.

### 7.2 첫 실발행

- **기본값 '익일 자동 전송' 상태에서 소액 실거래 1건**으로 한다. 이 설정은 **익영업일 15시 전까지 발행취소가 가능**하지만, '발행 즉시 전송'으로 바꾸면 **발행취소 자체가 불가**하다.
- **평일 오전에** 한다. 팝빌 고객센터는 평일 09~17시, 토·일·공휴일 휴무이고 국세청 전송은 익영업일 15시다 — **되돌릴 수 있는 창과 사람 지원이 닿는 시간이 어긋난다.**
- 발행 전 `GetChargeInfo` 로 환경(`IsTest`)과 `chargeMethod` 를 **눈으로 확인**한다.

## 8. 되돌릴 수 없는 것

| 항목 | 내용 |
|---|---|
| **파트너 계정 아이디** | 변경 절차가 공식 문서에 **없다.** 개인 이름 기반으로 지으면 담당자 교체 시 최상위 계정 회수가 어렵다 |
| **담당자 이메일** | LinkID/SecretKey 가 이 주소로만 오고 **재조회 경로가 문서에 없다** |
| **사업자번호** | 연동회원은 사업자번호 기준 **중복 등록 불가.** 잘못된 번호로 생성되면 단순 수정으로 끝나지 않을 수 있다 |
| **결제 방식** | 파트너 결제 ↔ 연동회원 결제. **2026-09-15 회신으로 확정 — *"운영 중 과금 방식의 변경은 시스템 절차상 어려움이 있음"***. 계약 시점에 확정해야 한다 |
| **계약 방법** | 법인인데 범용 인증서가 없으면 등기계약(최소 5일)이 일정에 그대로 얹힌다 |
| **국세청 신고 완료된 세금계산서** | 팝빌 원문: *"변경, 취소, 삭제, 폐기가 불가능합니다."* 수정세금계산서로 상쇄하는 것 외에 방법이 없고 **상쇄분도 국세청에 남는다.** 즉 `IsTest=False` 가 잘못 배포된 뒤의 실발행은 되돌릴 수 없다 |
| **웹훅 URL 유형** | 회원 URL ↔ 파트너 통합 URL. 변경 시 기존 URL 해지 선행 요청 |
| **포인트 과충전** | 약관 제12조: 사용내역이 있으면 잔여포인트의 **10% 차감** 후 환불(VAT 별도), 이체수수료 500원, 송금은 2·4째주 목요일. 환불신청서·사업자등록증·통장·신분증 사본 필요 → **한두 달 예상 사용량만 충전**하고 `getPartnerBalance` 알림으로 보충 |

## 10. 알려진 한계 — 팝빌에 물어야 답이 나오는 것

- **사업자등록 없이 LinkID 를 선발급받을 수 있는가** — 구조상 불가로 보이나 예외 운영 여부는 담당자만 안다. **SETIVE 일정의 최대 변수다.**
- **파트너 결제를 언제·어떻게 확정하는가**, 그리고 **운영 중 변경이 가능한가** — 두 폼 모두 선택란이 없다.
- **파트너 협의 단가** — 공개 요금(전자세금계산서 200원/건)은 직접 이용 기준이다. 파트너 원가·볼륨 구간·후불 심사 기준 전부 비공개.
- **테스트 포인트 지급 금액**과 '원가 발생 서비스' 범위.
- **API Key 재발급·교체(rotation) 경로** — 유출 시 절차가 있는지, 교체 중 중단이 생기는지 미확인.
- **LinkID/SecretKey 가 테스트와 운영에서 동일한 값인지** — 운영전환이 'IsTest 플래그 변경'으로만 기술돼 동일할 가능성이 높으나 명시 문구 없음.
- **타 파트너 소속 사업자의 이전 절차** — 한국 시장에서 흔할 상황인데 문서에 전혀 없다.
- **테스트 환경 연동회원 개수 상한**과 실재하지 않는 사업자번호 사용 가부.
- **FLE 키의 형식·알고리즘·패딩·인코딩**, SDK 의 `registTaxCertPFX` 가 암호화를 내부 처리하는지 호출자 몫인지 — 공개 규격 없음.
- **파트너 결제 시 연동회원별 사용내역 조회 API** — 포인트 API 에 `getBalance`(연동회원)와 `getPartnerBalance`(파트너)만 있고 연동회원별 사용내역 API 를 찾지 못했다.
- **`partner.popbill.com` 의 실체** — 로그인 벽이라 메뉴 구성 확인 불가.
- **각 구간 SLA** — 전자계약 1일 / 등기 5일 외에는 전부 "순차 처리"로만 안내된다.
- **계약서 실물 양식** — 단가표 포함 여부, 계약기간·자동갱신·해지예고 조항 확인 불가.
- **신규 사업자등록 직후 팝빌 접수가 바로 되는가** — 국세청 반영 시차(1~2일)가 팝빌에도 적용되는지 미확인.
- **실사용자 연동 후기를 확보하지 못했다.** 이 문서의 함정은 전부 공식 문서와 SDK 소스에서 직접 검증한 것이며, "실사용자가 어디서 시간을 잃었는가"는 미확인이다.
