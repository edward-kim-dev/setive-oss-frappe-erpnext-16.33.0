# ONT — 온톨로지 입력물

SETIVE ERP의 도메인 온톨로지 / 지식그래프 스키마 설계에 쓰이는 **개념 모델 문서**입니다.
[`docs/kb/`](../kb/)가 "코드가 지금 어떻게 생겼는지"를 기록한다면, 여기는 **"이 도메인에 어떤 개념과 관계가 존재하는지"** 를 코드와 독립적으로 기록합니다.

## 왜 분리하는가

ERP 구현은 바뀝니다. DocType 이름도, 필드도, 위저드 UI도 바뀝니다.
그러나 "국세청 업종코드는 6자리이고 KSIC 세세분류에 N:M으로 대응한다"는 사실은 제도가 개정되지 않는 한 그대로입니다.
온톨로지는 후자를 대상으로 설계해야 하므로, 전자와 섞이지 않게 물리적으로 갈라 둡니다.

## 문서에 반드시 들어가야 하는 것

ONT 문서는 산문 설명이 아니라 **추출 가능한 표**를 중심으로 씁니다. 아래 절을 순서대로 둡니다.

| 절 | 내용 | 온톨로지 대응 |
|---|---|---|
| 코드체계 (Code System) | 체계명 · 발행기관 · 코드 형식 · 판/개정 · 시행일 · 갱신주기 · 권위 출처 | 명명공간(namespace), 버전 |
| 개념 (Concept) | 개념명 · 식별자 · 정의 · 권위 출처 | 클래스 / 개별자 |
| 관계 (Relation) | 주체 · 술어 · 대상 · 카디널리티 · 근거 | 객체속성(ObjectProperty) |
| 시스템 매핑 | 개념 ↔ ERPNext DocType/필드 | 구현 바인딩 |
| 그래프 투영(안) | vertex/edge label 후보 | 스키마 초안 |
| 데이터 출처 | 원본 파일 · 취득 방법 · 실측 건수 | 인스턴스 적재 |
| 주의사항 | 시계열 단절, 부분대응, 미매핑 등 | 품질 제약 |

## 규칙

1. **카디널리티는 실측해서 적습니다.** "N:M 으로 보인다"가 아니라 원본 데이터에서 센 숫자를 근거와 함께 적습니다. 온톨로지의 `functional` / `cardinality` 제약이 여기서 나옵니다.
2. **권위 출처를 개념 단위로 명시합니다.** 같은 문서 안에서도 개념마다 소관 기관이 다를 수 있습니다(예: KSIC은 국가데이터처, 업종코드는 국세청).
3. **그래프 투영은 "(안)" 으로 표시합니다.** 확정 스키마가 아니라 제안임을 드러내, 나중에 실제 스키마와 혼동되지 않게 합니다.
4. **부정적 사실도 적습니다.** "건강보험공단은 자체 업종분류 체계가 없다" 같은 서술은 잘못된 모델링을 막아 주므로 개념만큼 값이 있습니다.
5. 프런트매터·링크·검증 규약은 [`docs/README.md`](../README.md)의 문서 작성 규약을 그대로 따릅니다.
